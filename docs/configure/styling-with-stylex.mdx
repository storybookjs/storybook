[StyleX](https://stylexjs.com) compiles styles at build time. Storybook doesn't compile StyleX itself: it uses the same StyleX bundler integration as your app. Set StyleX up for your app as the StyleX docs describe, then make the small additions on this page so Storybook gets the same styles, tokens, themes, and layer order.

<Callout variant="info">

Use the **same StyleX options** in Storybook as in your app. StyleX class names and variable names are hashes of your options and file paths. If `classNamePrefix`, `env`, `unstable_moduleResolution`, or `themeFileExtension` differ, or if Storybook compiles `src/` while your app consumes a built `dist/`, the hashes differ and tokens or themes seem to "not work". You don't need to make tokens public CSS variables.

</Callout>

`@storybook/nextjs-vite` compiles with SWC and doesn't read your Babel config. Add `@stylexjs/unplugin` in `viteFinal`, with the same options as the StyleX Babel plugin in your app:

## Tokens from a package

`defineVars` tokens that come from an installed package must be compiled by StyleX. If Vite pre-bundles the package instead, the story fails with `Unexpected 'stylex.defineVars' call at runtime`.

- With `@stylexjs/unplugin`, list the package in `externalPackages`. The plugin finds most StyleX packages by itself, but not packages whose `exports` don't include `./package.json`.
- With another Vite integration, add the package to `optimizeDeps.exclude`.
- With Next.js, add the package to `transpilePackages` and to the PostCSS plugin's `include`.

## Layer order and resets

With `useCSSLayers`, StyleX puts its rules in `@layer priority1`, `priority2`, and so on. Storybook adds no reset and no layers to your stories, but your own reset can still win over StyleX:

- A reset in a layer that is declared **after** the StyleX layers wins. Tell StyleX to declare your reset layer first with `useCSSLayers: { before: ['reset'] }`, or declare the order yourself in `.storybook/preview-head.html` before any other CSS loads:

  <CodeSnippets path="stylex-preview-head-layers.md" />

- A reset that is **not in a layer** wins over every layered rule. Put your reset in a layer.
- Don't turn layers off only in production (for example `useCSSLayers: process.env.NODE_ENV !== 'production'`). The cascade in your static Storybook and your app would then differ from the one in development.

## Troubleshooting

### Styles appear late in development

In development, the StyleX Vite plugin serves its CSS separately and updates it as modules load. A story that loads lazily can render for a moment (about 150 ms) before its styles arrive. Run visual tests against a static build (`storybook build`), which has all styles from the start.

### Storybook doesn't finish loading in large projects

If Storybook stalls while it loads a project with many StyleX components:

1. Use `@stylexjs/unplugin` or the StyleX PostCSS plugin. The older `vite-plugin-stylex` waits for Vite to be idle, which can block Vite's dependency optimizer.
2. Use Vite 5.4.3 or later, which fixes deadlocks with plugins that wait for Vite to be idle.
3. If you keep a plugin that waits for Vite to be idle, turn off `optimizeDeps.holdUntilCrawlEnd`:

<CodeSnippets path="stylex-vite-final-hold-until-crawl-end.md" />

To time your setup, Storybook's repository has a script that generates 250 StyleX components in a sandbox and measures how long stories take to load: `scripts/stylex/scale-timing.ts`.
