# plan.nextjs-webpack: cause

- File and line: `.storybook/main.ts` after `nextjs-to-nextjs-vite` runs. The `framework.name` is now `@storybook/nextjs-vite`, and the `webpackFinal` block with `TsconfigPathsPlugin` is no longer applied. The `tsconfig.json` `paths` (`@mantine/*`, `@mantinex/*`, `@mantine-tests/*`, `@docs/*` to `packages/*/src`) are therefore not used by the Vite build.
- Why it fails: the workspace packages' `package.json` `main`/`module`/`exports` point to `esm/`, `cjs/` and `lib/` build output that is not built in this checkout. Vite resolves `@mantinex/code-highlight` and the other workspace packages through those entries and fails with `Failed to resolve entry for package "@mantinex/code-highlight"`. Evidence: `plan-vite-dev-fail.log`, `plan-vite-iframe.png` (error overlay on `.storybook/preview.tsx:7:39`).
- Fix tried (workaround): a `viteFinal` in `.storybook/main.ts` that sets `resolve.alias` to map the workspace package names to `packages/@<scope>/<name>/src/index.ts`, and an alias for `console` to `.storybook/console-shim.ts`. After it, the dev server pre-bundles with 0 "Failed to resolve entry" errors and the story renders (`plan-vite-iframe-unblocked.png`, `plan-vite-browser-2.png`).
