## Write stories with Svelte CSF

Svelte CSF lets you write stories in Svelte's template syntax, in files that end in `.stories.svelte`. It is built into `@storybook/sveltekit`, so you don't need an addon.

In a stories file, call [`preview.meta`](../../writing-stories/csf/api.mdx#previewmeta) in a `<script module>` block. It returns the `Story` component, which you use once per story. The content between the `Story` tags is passed to the component as its `children` snippet. This example uses the `Button` component from [Component documentation](#component-documentation):

```svelte title="Button.stories.svelte"
<script module lang="ts">
  import preview from '../.storybook/preview';

  import Button from './Button.svelte';

  const { Story } = preview.meta({
    component: Button,
  });
</script>

<Story name="Primary" args={{ primary: true }}>Primary</Story>

<Story name="Large" args={{ size: 'large' }}>Large</Story>
```

The `stories` field in `.storybook/main.ts` must include the `svelte` extension, for example `'../src/**/*.stories.@(js|ts|svelte)'`. `storybook init` sets this for you.

A Svelte CSF file compiles to regular [CSF](../../writing-stories/csf/index.mdx) stories, so you can use `.stories.svelte` and `.stories.ts` files in the same project. Stories files that use `defineMeta` from `@storybook/sveltekit` work too. The [CSF 4 upgrade guide](../../writing-stories/csf/upgrade.mdx) explains how to move them to `preview.meta`.

To learn more about Svelte CSF, read these guides:

- [How to write stories](../../writing-stories/index.mdx), including children and custom templates
- [CSF API](../../writing-stories/csf/api.mdx), including `extend` to build a story from another one
- [TypeScript](../../writing-stories/typescript.mdx), including `meta.type` for args that only a template uses
- [Args](../../writing-stories/args.mdx), [decorators](../../writing-stories/decorators.mdx), and [parameters](../../writing-stories/parameters.mdx)

## Component documentation

Storybook 11 reads Svelte component props on the server by default, with [`svelte2tsx`](https://github.com/sveltejs/language-tools/tree/master/packages/svelte2tsx) and the [`typescript`](../../configure/integration/typescript.mdx) package (TypeScript 5.9 or 6, even in JavaScript projects, where it reads types from JSDoc comments). New projects need no docgen configuration and no extra packages. Storybook uses the props for [controls](../../essentials/controls.mdx), [autodocs](../../writing-docs/autodocs.mdx), the code snippets in the [Code panel](../../writing-docs/code-panel.mdx), and the [components manifest](../../ai/manifests.mdx) that AI agents read.

Without a usable `typescript` package, Storybook prints a warning that tells you what to install, and reads no props: controls and autodocs then show only the [`argTypes`](../../api/arg-types.mdx#manually-specifying-argtypes) that you write yourself. TypeScript 7 has no compiler API that Storybook can use for Svelte. To keep `tsc` on TypeScript 7, install TypeScript 6 side by side, as [TypeScript 7](../../configure/integration/typescript.mdx#typescript-7) explains.

<Callout variant="info">

The Storybook 10 builder-based docgen is still available, but it is deprecated. It will be removed in Storybook 12. To use it, set [`features.docgenServer: false`](../../api/main-config/main-config-features.mdx#docgenserver) in your main config. See the [`docgen`](#docgen) option.

</Callout>

Storybook reads this information from a component:

- The props and their types, from the type of `$props()`. In JavaScript, write the type in a JSDoc `@type` comment.
- The default values, from the destructuring of `$props()`.
- The JSDoc comment of each prop, and its tags.
- The component description, from a `<!-- @component -->` comment.
- Which props are `$bindable()`.

For example:

```svelte title="Button.svelte"
<!--
  @component
  The main action on a page.
-->
<script lang="ts">
  import type { Snippet } from 'svelte';

  interface Props {
    /** Makes the button stand out. Use it for one action per page. */
    primary?: boolean;
    size?: 'small' | 'medium' | 'large';
    onclick?: (event: MouseEvent) => void;
    children?: Snippet;
  }

  let { primary = false, size = 'medium', onclick, children }: Props = $props();
</script>
```

In the Controls panel, `size` gets a control that offers its three values. `children` is in the **slots** category and `onclick` is in the **events** category, without a control. Props that a component gets from a whole attribute interface, such as `HTMLButtonAttributes`, are not listed. Props that it picks from one, such as `Pick<HTMLButtonAttributes, 'disabled'>`, are.

The Code panel shows the story as Svelte markup. The snippet starts with a `<script>` block that imports the components and values the story uses. By default, it shows the story as you wrote it, so it does not change when you change a control.

## Configure

This section covers SvelteKit support and configuration options.

### Supported features

All Svelte language features are supported out of the box, as the Storybook framework uses the Svelte compiler directly.
However, SvelteKit has some [Kit-specific modules](https://kit.svelte.dev/docs/modules) that aren't supported. Here's a breakdown of what will and will not work within Storybook:

| Module                                                                   | Status                 | Note                                                                                                                                                                                                                                                                  |
| ------------------------------------------------------------------------ | ---------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| [`$app/env`](https://svelte.dev/docs/kit/$app-env)                       | ✅ Supported           | `version` is always empty in Storybook. The deprecated `$app/environment` works the same way.                                                                                                                                                                         |
| [`$app/env/public`](https://svelte.dev/docs/kit/$app-env-public)         | 🚧 Partially supported | Static variables are supported. Dynamic variables are always `undefined`, because Storybook has no server to provide them.                                                                                                                                            |
| [`$app/forms`](https://svelte.dev/docs/kit/$app-forms)                   | ⚠️ **Experimental**    | See [How to mock](#how-to-mock).                                                                                                                                                                                                                                      |
| [`$app/manifest`](https://svelte.dev/docs/kit/$app-manifest)             | 🚧 Partially supported | Only has values in development mode. In a built Storybook, every list is empty.                                                                                                                                                                                       |
| [`$app/navigation`](https://svelte.dev/docs/kit/$app-navigation)         | ⚠️ **Experimental**    | See [How to mock](#how-to-mock).                                                                                                                                                                                                                                      |
| [`$app/paths`](https://svelte.dev/docs/kit/$app-paths)                   | ✅ Supported           |                                                                                                                                                                                                                                                                       |
| [`$app/state`](https://svelte.dev/docs/kit/$app-state)                   | ⚠️ **Experimental**    | See [How to mock](#how-to-mock).                                                                                                                                                                                                                                      |
| [`$env/*/public`](https://svelte.dev/docs/kit/$env-static-public)        | 🚧 Partially supported | Deprecated by SvelteKit. Works the same way as `$app/env/public`.                                                                                                                                                                                                     |
| `#lib`                                                                   | ✅ Supported           |                                                                                                                                                                                                                                                                       |
| [`@sveltejs/kit/*`](https://svelte.dev/docs/kit/@sveltejs-kit)           | ✅ Supported           |                                                                                                                                                                                                                                                                       |
| [`$app/env/private`](https://svelte.dev/docs/kit/$app-env-private)       | ⛔ Not supported       | This is a server-side feature, and Storybook renders all components on the client. Storybook fails to load stories that import it. Mock the module that imports it with a [mock file](../../writing-stories/mocking-data-and-modules/mocking-modules.mdx#mock-files). |
| [`$app/server`](https://svelte.dev/docs/kit/$app-server)                 | ⛔ Not supported       | This is a server-side feature, and Storybook renders all components on the client. Storybook fails to load stories that import it. Mock the module that imports it with a [mock file](../../writing-stories/mocking-data-and-modules/mocking-modules.mdx#mock-files). |
| [`$env/*/private`](https://svelte.dev/docs/kit/$env-static-private)      | ⛔ Not supported       | Deprecated by SvelteKit. Works the same way as `$app/env/private`.                                                                                                                                                                                                    |
| [Remote functions](https://svelte.dev/docs/kit/remote-functions)         | ⛔ Not supported       | Storybook has no server to run them on, and building Storybook fails when a story imports one.                                                                                                                                                                        |
| [`$app/service-worker`](https://svelte.dev/docs/kit/$app-service-worker) | ⛔ Not supported       | This is a service worker feature, which does not apply to Storybook.                                                                                                                                                                                                  |

### Static assets

Storybook serves the files in your SvelteKit `static` directory at the root, like SvelteKit does. If you set `files.assets` to another directory in your SvelteKit config, add that directory to [`staticDirs`](../../configure/integration/images-and-assets.mdx#serving-static-files-via-storybook-configuration) so that `storybook build` includes it.

## API

### Parameters

This framework contributes the following [parameters](../../writing-stories/parameters.mdx) to Storybook, under the `sveltekit_experimental` namespace:

#### `forms`

Type: `{ enhance: () => void }`

Provides mocks for the [`$app/forms`](https://svelte.dev/docs/kit/$app-forms) module.

##### `forms.enhance`

Type: `() => void`

A callback that will be called when a form with [`use:enhance`](https://kit.svelte.dev/docs/form-actions#progressive-enhancement-use-enhance) is submitted.

#### `hrefs`

Type: `Record<[path: string], (to: string, event: MouseEvent) => void | { callback: (to: string, event: MouseEvent) => void, asRegex?: boolean }>`

If you have an `<a />` tag inside your code with the `href` attribute that matches one or more of the links defined (treated as regex based if the `asRegex` property is `true`) the corresponding `callback` will be called. If no matching `hrefs` are defined, an action will be logged to the [Actions panel](../../essentials/actions.mdx). See [Mocking links](#mocking-links) for an example.

#### `navigation`

Type: See [SvelteKit docs](https://svelte.dev/docs/kit/$app-navigation)

Provides mocks for the [`$app/navigation`](https://svelte.dev/docs/kit/$app-navigation) module.

##### `navigation.goto`

Type: See [SvelteKit docs](https://svelte.dev/docs/kit/$app-navigation#goto)

A callback that will be called whenever [`goto`](https://svelte.dev/docs/kit/$app-navigation#goto) is called. If no function is provided, an action will be logged to the [Actions panel](../../essentials/actions.mdx).

##### `navigation.pushState`

Type: See [SvelteKit docs](https://svelte.dev/docs/kit/$app-navigation#pushState)

A callback that will be called whenever [`pushState`](https://svelte.dev/docs/kit/$app-navigation#pushState) is called. If no function is provided, an action will be logged to the [Actions panel](../../essentials/actions.mdx).

##### `navigation.replaceState`

Type: See [SvelteKit docs](https://svelte.dev/docs/kit/$app-navigation#replaceState)

A callback that will be called whenever [`replaceState`](https://svelte.dev/docs/kit/$app-navigation#replaceState) is called. If no function is provided, an action will be logged to the [Actions panel](../../essentials/actions.mdx).

##### `navigation.invalidate`

Type: See [SvelteKit docs](https://svelte.dev/docs/kit/$app-navigation#invalidate)

A callback that will be called whenever [`invalidate`](https://svelte.dev/docs/kit/$app-navigation#invalidate) is called. If no function is provided, an action will be logged to the [Actions panel](../../essentials/actions.mdx).

##### `navigation.invalidateAll`

Type: See [SvelteKit docs](https://svelte.dev/docs/kit/$app-navigation#invalidateAll)

A callback that will be called whenever [`invalidateAll`](https://svelte.dev/docs/kit/$app-navigation#invalidateAll) is called. If no function is provided, an action will be logged to the [Actions panel](../../essentials/actions.mdx).

##### `navigation.refreshAll`

Type: See [SvelteKit docs](https://svelte.dev/docs/kit/$app-navigation#refreshAll)

A callback that will be called whenever [`refreshAll`](https://svelte.dev/docs/kit/$app-navigation#refreshAll) is called. If no function is provided, an action will be logged to the [Actions panel](../../essentials/actions.mdx).

##### `navigation.afterNavigate`

Type: See [SvelteKit docs](https://svelte.dev/docs/kit/$app-navigation#afterNavigate)

An object that will be passed to the [`afterNavigate`](https://svelte.dev/docs/kit/$app-navigation#afterNavigate) function, which will be invoked when the `onMount` event fires. Storybook merges it into a navigation with `type: 'enter'` and `shallow: false`, so the callback always gets a full navigation object.

#### `state`

Type: See [SvelteKit docs](https://svelte.dev/docs/kit/$app-state)

Provides mocks for the [`$app/state`](https://svelte.dev/docs/kit/$app-state) module.

##### `state.navigating`

Type: See [SvelteKit docs](https://svelte.dev/docs/kit/$app-state#navigating)

A partial version of the [`navigating`](https://svelte.dev/docs/kit/$app-state#navigating) store.

##### `state.page`

Type: See [SvelteKit docs](https://svelte.dev/docs/kit/$app-state#page)

A partial version of the [`page`](https://svelte.dev/docs/kit/$app-state#page) store.

##### `state.updated`

Type: `{ current: boolean }`

An object representing the current value of [`updated`](https://svelte.dev/docs/kit/$app-state#updated). You can also access `updated.check()`, which will be a no-op.

### Options

You can pass an options object for additional configuration if needed:

<CodeSnippets path="sveltekit-framework-options.md" />

The available options are:

#### `builder`

Type: `Record<string, any>`

Configure options for the [framework's builder](../../api/main-config/main-config-framework.mdx#optionsbuilder). For Sveltekit, available options can be found in the [Vite builder docs](../../builders/vite.mdx).

#### `docgen`

Type: `boolean`

Default: `true`

Turns builder docgen on or off. Builder docgen reads your components in the Vite build, and Storybook only uses it when [`docgenServer`](../../api/main-config/main-config-features.mdx#docgenserver) is off. Like the server, it needs a usable `typescript` package. `docgenServer` is on by default, so this option has no effect unless you turn the server off. See [Component documentation](#component-documentation).

<Callout variant="warning">

Builder docgen is deprecated and will be removed in Storybook 12. Storybook warns when it runs, because your `.storybook/main.ts` sets `docgenServer: false`. Remove that setting to use server-side docgen.

</Callout>

To turn docgen off completely, turn off both `docgenServer` and builder docgen:

<CodeSnippets path="svelte-framework-options-docgen.md" />

##### When to turn docgen off completely

Turning docgen off can improve build performance for large projects, but [argTypes won't be inferred automatically](../../api/arg-types.mdx#automatic-argtype-inference), which will prevent features like [Controls](../../essentials/controls.mdx) and [docs](../../writing-docs/autodocs.mdx) from working as expected. To use those features, you will need to [define `argTypes` manually](../../api/arg-types.mdx#manually-specifying-argtypes).
