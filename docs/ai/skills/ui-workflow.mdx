<If renderer={['react', 'vue', 'angular', 'svelte', 'web-components']}>

The `ui-workflow` skill gives your agent one workflow for every UI change: reuse your components, write stories, test, and show you the result. You get UI that fits your project, stories that prove it works, and one link to review it.

## When your agent uses it

With the [Storybook section in `AGENTS.md`](../connect.mdx#tell-your-agent-when-to-use-the-skills), your agent uses the skill when it:

- Creates, changes, or deletes a component, story, style, theme, or design token
- Runs or fixes story tests
- Shows you components or stories that you ask to see

Without that section, ask for the skill by name, for example "Use the ui-workflow skill to add a loading state to the user list".

## What the agent does

For example, you ask your agent to "Build a login form". The agent:

1. **Looks up your components.** Before it edits any file, it lists the components in your Storybook and reads the props and examples of the ones it needs, such as `TextField` and `Button`. It uses only documented props. See [Component info](./component-info.mdx).
2. **Writes the component and its stories.** It writes one story for each state the component can reach, such as empty, filled, invalid, and submitting, with realistic data. Interactive states get a [play function](../../writing-stories/play-function.mdx) that tests the behavior.
3. **Mocks what the stories need.** It mocks [network requests](../../writing-stories/mocking-data-and-modules/mocking-network-requests.mdx) with MSW and sets up MSW if your project doesn't have it. For other dependencies, it uses [module mocks](../../writing-stories/mocking-data-and-modules/mocking-modules.mdx).
4. **Runs the story tests.** If your project has the [Vitest addon](../../writing-tests/integrations/vitest-addon/index.mdx), it runs [component tests](../../writing-tests/index.mdx) with [accessibility checks](../../writing-tests/accessibility-testing.mdx) after each change, and one full run before it finishes. It fixes failures and doesn't finish with failing tests.
5. **Finds every affected story.** It finds the stories for the components it changed, and the stories of other components that use them, such as a `LoginPage` that renders the form.
6. **Publishes a review.** It groups those stories into a [review](./agentic-review.mdx) and ends its reply with a link to it.

The agent follows your project's conventions. For example, it writes stories in the [story format](../../writing-stories/csf/index.mdx) that your project uses, and it doesn't rewrite your existing stories to match its own rules.

### Accessibility issues

If you are using the [accessibility addon](../../writing-tests/accessibility-testing.mdx), the agent fixes semantic accessibility issues, such as missing labels, roles, or alt text. For visual issues, such as low color contrast, it doesn't change your design. It describes the problem, gives you two or three options, and asks you to choose.

### Requests to see UI

When you ask to see something, such as "Show me the Button in all its states", the agent publishes a [review](./agentic-review.mdx) of those stories without changing any files.

## The dev server

The review needs a running Storybook dev server. The other steps don't. The agent uses the dev server that's already running for your project. If none is running, the agent starts it with your project's Storybook script, such as `npm run storybook`. The agent leaves the dev server running when it's done, so you can keep looking at your stories.

## Requirements

- Storybook 11 and a [supported framework](../connect.mdx#supported-frameworks)

These addons are optional. Without one, the agent skips the step that needs it:

- [Vitest addon](../../writing-tests/integrations/vitest-addon/index.mdx), to run story tests. It needs the Vite builder.
- [Accessibility addon](../../writing-tests/accessibility-testing.mdx), to run accessibility checks with the story tests.

## Tips

- **Monorepos:** the agent runs Storybook commands from the package where Storybook is installed, such as `packages/ui`.
- **Sandboxed agents:** some agents block network access and ports by default. Allow the agent to run Storybook commands and start the dev server.
- **Change the workflow:** to leave out a step, such as the review, edit the [Storybook section in `AGENTS.md`](../connect.mdx#tell-your-agent-when-to-use-the-skills). The skill skips the steps that your instructions leave out.
