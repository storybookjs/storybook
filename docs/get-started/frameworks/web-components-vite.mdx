## FAQ

### How do I use Stencil with static Storybook builds?

If you register Stencil components with `defineCustomElements()` from the generated loader, enable Stencil's import injection so Vite can include the lazy-loaded component entry files in the static Storybook build.

For Stencil 4.26 and later:

```ts title="stencil.config.ts"
import type { Config } from '@stencil/core';

export const config: Config = {
  extras: {
    enableImportInjection: true,
  },
};
```

For older Stencil versions, use `experimentalImportInjection: true` instead.

### Why don't my Stencil components load after building for production?

If you register Stencil components using the generated loader, first enable [Stencil's import injection](https://stenciljs.com/docs/config-extras#enableimportinjection) as described above. This allows Vite to discover the lazy-loaded component entry files during a production build.

If your components still fail to render after `storybook build`, check whether the generated JavaScript chunks are available at the URLs requested by the browser.

If you can't enable import injection, or the browser still requests missing JavaScript chunks after `storybook build`, you can configure Storybook to copy Stencil's lazy-loaded ESM output into the built preview.

```ts
staticDirs: [{ from: '../dist/esm', to: '/assets' }],
```

This example assumes that Stencil generates its ESM chunks in `dist/esm` and that the built preview requests them from `/assets`. Adjust these paths to match your project's output and the URLs requested by the browser.

Alternatively, if your Stencil project uses the `dist-custom-elements` output target, you can import generated components directly in `.storybook/preview.ts`:

```ts
import '../dist/components/my-component.js';
```

This direct import registers the component only when the `dist-custom-elements` output target uses `customElementsExportBehavior: 'auto-define-custom-elements'`. Otherwise, import `defineCustomElement` from the generated component file and call it explicitly.

This lets Vite include the imported component in its production bundle without relying on Storybook's `staticDirs` configuration.

See [Images, fonts, and assets](../../configure/integration/images-and-assets.mdx) for more information about serving static files.
