<If renderer={['react', 'vue', 'angular', 'svelte', 'web-components']}>

The UI workflow gives your agent one way to make every UI change: reuse your components, write stories, and test them. You get UI that fits your project and stories that prove it works. When you want to see the result, ask for a review.

## How it works

The workflow is the [Storybook section in `AGENTS.md`](../connect.mdx#tell-your-agent-when-to-use-the-skills). It lists four steps in order:

| Step | What the agent does                                                                                                            |
| ---- | ------------------------------------------------------------------------------------------------------------------------------ |
| 1    | Looks up the components to reuse, with their props and usage examples, with the [`component-docs`](./component-docs.mdx) skill |
| 2    | Writes stories for every component it creates or changes, with the [`write-stories`](./write-stories.mdx) skill                |
| 3    | Runs the story tests after every change with `npx storybook tools test run`, and fixes what fails                              |
| 4    | Ends its reply with a line that tells you about the [`ui-review`](./ui-review.mdx) skill, after a change you can see           |

Your agent opens the skills of steps 1 and 2 before it edits any file, then follows each skill at its step. Steps 3 and 4 need no skill: step 3 is the command itself, and step 4 is the line "Use the /ui-review skill to see the changed components in Storybook". The agent creates a review only when you ask for it. See [UI review](./ui-review.mdx).

## When your agent follows it

With the Storybook section in `AGENTS.md`, your agent follows the workflow for every change to how your UI looks: when it creates, changes, or deletes a component, story, style, theme, or design token.

Some steps also run on their own:

- `component-docs`, when you ask about a component's props, API, or usage
- [`ui-review`](./ui-review.mdx), when you ask for a review or to see components or stories

Without that section, an agent connected only through skills doesn't follow the workflow automatically. It can still use a skill that fits its task, and you can ask for one by name, for example "Use the write-stories skill to add stories for the user list". An agent connected to the [MCP server](../reference/mcp-server.mdx) receives the workflow from the server instead.

## What the agent does

For example, you ask your agent to "Build a login form". The agent:

1. **Looks up your components.** Before it edits any file, it lists the components in your Storybook and reads the props and examples of the ones it needs, such as `TextField` and `Button`. It uses only documented props. See [Component docs](./component-docs.mdx).
2. **Writes the component and its stories.** It writes one story for each state the component can reach, such as empty, filled, invalid, and submitting, with realistic data. Interactive states get a [play function](../../writing-stories/play-function.mdx) that tests the behavior. It mocks network requests and modules that the stories need. See [Write stories](./write-stories.mdx).
3. **Runs the story tests.** If your project has the [Vitest addon](../../writing-tests/integrations/vitest-addon/index.mdx), it runs the [component tests](../../writing-tests/index.mdx) of the stories its change affects, with [accessibility checks](../../writing-tests/accessibility-testing.mdx), after each change. See [Test stories](./test-stories.mdx).
4. **Offers a review.** It ends its reply with a line that offers the `ui-review` skill. When you ask for the review, it finds the stories that its change affects, such as those of a `LoginPage` that renders the form, and groups them into a review. See [UI review](./ui-review.mdx).

## Change the workflow

To change the workflow, remove both markers around the Storybook section in `AGENTS.md`, then edit the steps. For example, delete the step that tells you about the review, or tell the agent to create a review after every change. Storybook doesn't change a section without markers when you upgrade.

A step also skips itself when your project can't do it. The test step is left out when the main config of your Storybook doesn't list the Vitest addon. With the [MCP server](../reference/mcp-server.mdx), a step is left out when you turn off the [toolset](../reference/mcp-server.mdx#toolsets) that it needs.

## Requirements

- Storybook 11 and a [supported framework](../connect.mdx#supported-frameworks)

These addons are optional. Without one, the agent skips the step that needs it:

- [Vitest addon](../../writing-tests/integrations/vitest-addon/index.mdx), to run story tests. It needs the Vite builder.
- [Accessibility addon](../../writing-tests/accessibility-testing.mdx), to run accessibility checks with the story tests.

## Tips

- **Monorepos:** the agent runs Storybook commands from the package where Storybook is installed, such as `packages/ui`.
- **Sandboxed agents:** some agents block network access and ports by default. Allow the agent to run Storybook commands and start the dev server.
