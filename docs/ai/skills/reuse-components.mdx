<If renderer={['react', 'vue', 'angular', 'svelte', 'web-components']}>

The `component-docs` skill lets your agent look up the components in your Storybook, with their props and usage examples. Your agent then reuses the components you have instead of building new ones, and uses only the props they really have.

## When your agent uses it

With the [Storybook section in `AGENTS.md`](../connect.mdx#tell-your-agent-when-to-use-the-skills), your agent uses the skill when it:

- Looks for an existing component to reuse
- Answers a question about a component's props, API, or usage, such as "Which props does `Card` take?"

For UI changes, your agent uses the [UI workflow](./ui-workflow.mdx) instead. Its first step is the same component lookup.

## What the agent reads

The agent reads your components' documentation from your Storybook, not from source files or `node_modules`:

- A list of every component and docs page
- For each component: its description, its props with their types, and the code of its first stories
- The code of any other story, when the first stories don't show the usage it needs

This information comes from the [components manifest](../reference/manifests.mdx). The agent reads source files only when your Storybook has no documentation for what it needs.

## Components from other Storybooks

If your Storybook uses [composition](../../sharing/storybook-composition.mdx), the agent also sees the components of each composed Storybook that has a components manifest. For example, an app's Storybook can compose your design system's published Storybook, and the agent finds components in both.

## Get better results

The agent can only reuse what your Storybook documents. Component descriptions, prop descriptions, and stories that show real usage all help it choose and use the right component. See the [best practices](../best-practices.mdx).
