Connect your coding agent to Storybook so it can use your components, stories, and tests. We recommend [skills](#install-the-skills), which work with any agent that can run shell commands. Use the [MCP server](#mcp-server) if your agent can't run shell commands.

<Callout variant="info">

Some skills aren't available for every framework. See [supported frameworks](#supported-frameworks) to check yours.

</Callout>

## Install the skills

Skills are short instruction files in your repository. Each one tells your agent when to use it and gets its full instructions from your installed Storybook. Because skills live in your repository, every person and agent working on the project gets the same version, and that version matches your Storybook.

When you run [`storybook init`](../api/cli-options.mdx#init), it asks whether to install the skills. The default answer is yes.

When you [upgrade](../releases/upgrading.mdx) from Storybook 10, the `skills` automigration offers to install them. It asks only once.

To install the skills at any other time, run this command from the root of your project:

<CodeSnippets path="storybook-automigrate-skills.md" />

Every install method adds the same files:

- The skills: `storybook-init`, [`storybook-setup`](./skills/setup.mdx), `storybook-upgrade`, [`component-info`](./skills/component-info.mdx), and [`ui-workflow`](./skills/ui-workflow.mdx). They're installed for Claude Code (`.claude/skills/`) and for other agents (`.agents/skills/`).
- `skills-lock.json`, which records the installed version.
- A Storybook section in `AGENTS.md` (see below)

Commit these files so everyone on your team gets them. When you run [`storybook upgrade`](../releases/upgrading.mdx), Storybook updates the skills to match the new version.

<details>
<summary>Plugins</summary>

Storybook also has plugins for [Claude Code](https://github.com/storybookjs/storybook/tree/next/code/lib/claude-plugin#readme) and [Codex](https://github.com/storybookjs/storybook/tree/next/code/lib/codex-plugin#readme). A plugin installs the same skills once for every project on your machine. We recommend the skills in your repository instead, because they always match the Storybook version of each project, and your whole team gets them.

</details>

## Tell your agent when to use the skills

Agents don't use the Storybook skills on their own. The section that Storybook adds to `AGENTS.md` tells your agent to use `ui-workflow` for UI changes and `component-info` for questions about components:

```md title="AGENTS.md"
<!-- BEGIN:storybook-skills -->
<!-- Storybook updates this section on upgrade. Remove both markers to keep your own edits. -->

## Storybook skills

For each of these tasks, invoke its Storybook skill first, before you edit any file, and follow it:

- `ui-workflow`: you create, change, or delete a component, story, style, theme, or design token, or otherwise change how the UI looks; you run or fix story tests; or the user asks to see components or stories. It looks up the components to reuse, updates your stories, runs the tests, and publishes a review of the results.
- `component-info`: you look for an existing component to reuse instead of building a new one, or the user asks about the project's components: which ones exist, which one fits a use case, which props one takes (for example, for accessibility), or where the component library has gaps. It lists the project's components with their props and usage examples.

<!-- END:storybook-skills -->
```

Storybook replaces the text between the markers when you upgrade. To customize the section, remove both markers, then edit the text. Storybook doesn't change a section without markers. To stop your agent from using the skills on its own, remove the whole section. You can still ask your agent to use a skill by name, for example "Use the ui-workflow skill to add a dark mode toggle".

If your project has a `CLAUDE.md` that doesn't import `AGENTS.md`, Storybook adds the same section to `CLAUDE.md`, so Claude Code sees it too.

## MCP server

While we recommend using the skills for most agents, Storybook also provides an MCP server as an alternative way for your agent to interact with your Storybook instance.

**Upgrade to skills**

If you used the [MCP server](./reference/mcp-server.mdx) in Storybook 10, the `skills` automigration installs the skills but keeps your MCP setup. To prevent your agent from getting two sets of instructions for the same work, remove `@storybook/addon-mcp` with [`storybook remove`](../api/cli-options.mdx#remove), and remove the Storybook MCP server from your agent's configuration. Also remove any instructions about the MCP server from `AGENTS.md`.

**Alternative for agents that can't run shell commands**

If your agent can't run shell commands, [connect it to the MCP server instead](./reference/mcp-server.mdx). The MCP server gives your agent the same capabilities as the skills, but it needs a running Storybook dev server.

## Connect to a published Storybook

You can also connect your agent to a published Storybook instead of running it locally. To give your agent access to component docs from a Storybook that doesn't run on your machine, such as your team's design system, see [Use a published Storybook](./published-storybook.mdx).

## Supported frameworks

Skills are available for these frameworks:

| Renderer                | Frameworks                                          | [Setup](./skills/setup.mdx) | [UI workflow](./skills/ui-workflow.mdx) | [Component info](./skills/component-info.mdx) |
| ----------------------- | --------------------------------------------------- | --------------------------- | --------------------------------------- | --------------------------------------------- |
| React (Setup supported) | `react-vite`, `nextjs-vite`, `tanstack-react`       | Yes                         | Yes                                     | Yes                                           |
| React (other)           | `react-webpack5`, `nextjs`, `react-native-web-vite` | No                          | Yes                                     | Yes                                           |
| Vue 3                   | `vue3-vite`                                         | Yes                         | Yes                                     | Yes                                           |
| Angular                 | `angular-vite`                                      | Yes                         | Yes                                     | Yes                                           |
| Svelte                  | `svelte-vite`, `sveltekit`                          | No                          | Yes                                     | Yes                                           |
| Web Components          | `web-components-vite`                               | No                          | Yes                                     | Yes                                           |

The `storybook-init` and `storybook-upgrade` skills work with every framework in this table.
The [MCP server](./reference/mcp-server.mdx) supports the same renderers.
