## `check`

Type: `boolean`

Optionally run [fork-ts-checker-webpack-plugin](https://github.com/TypeStrong/fork-ts-checker-webpack-plugin). Note that because this uses a Webpack plugin, it is only available when using the [Webpack builder](../../builders/webpack.mdx).

## `docgenSpecifier`

Type: `string`

Default: `'typescript'`

The TypeScript package that Storybook loads to read your component types for Controls and the Docs args table. Storybook resolves it as if your main config imported it, so the value is a package name or a path to the package's folder, absolute or relative to the config directory. Do not include a subpath such as `/sync`. For Angular, `@storybook/angular-vite` reads this option.

Storybook reads the package's version and uses the API that version has: the compiler API of TypeScript 5.9 and 6, or the API of TypeScript 7.1 and newer, which is faster. TypeScript 7.0 has neither.

Set this option when the `typescript` package must stay on TypeScript 6, for example because Angular's compiler or `typescript-eslint` requires it, and you install TypeScript 7.1 or newer under another name. The [TypeScript 7 announcement](https://devblogs.microsoft.com/typescript/announcing-typescript-7-0/) recommends this side-by-side setup in `package.json`:

```json
{
  "devDependencies": {
    "@typescript/native": "npm:typescript@^7.1",
    "typescript": "npm:@typescript/typescript6@^6.0.2"
  }
}
```

## `reactDocgen`

(⛔️ **Deprecated**)

Type: `'react-docgen' | 'react-docgen-typescript' | false`

Default:

- `false`: if `@storybook/react` is not installed
- `'react-docgen'`: if `@storybook/react` is installed and [`docgenServer`](./main-config-features.mdx#docgenserver) is off

Configures which library, if any, Storybook uses to parse React components on the legacy builder-based path: [react-docgen](https://github.com/reactjs/react-docgen) or [react-docgen-typescript](https://github.com/styleguidist/react-docgen-typescript). Set to `false` to disable parsing React components. `react-docgen-typescript` invokes the TypeScript compiler, which makes it slow but generally accurate. `react-docgen` performs its own analysis, which is much faster but incomplete.

Builder docgen is deprecated and will be removed in Storybook 12.
This option only applies when [`docgenServer`](./main-config-features.mdx#docgenserver) is off, and Storybook warns when it runs.
Storybook 11 enables server-side docgen by default.

## `reactDocgenTypescriptOptions`

(⛔️ **Deprecated**)

Type: `ReactDocgenTypescriptOptions`

Configures the options to pass to `react-docgen-typescript-plugin` if `react-docgen-typescript` is enabled and [`docgenServer`](./main-config-features.mdx#docgenserver) is off. See docs for available options [for Webpack projects](https://github.com/hipstersmoothie/react-docgen-typescript-plugin) or [for Vite projects](https://github.com/joshwooding/vite-plugin-react-docgen-typescript).

Server-side docgen does not translate these options.
Like [`reactDocgen`](#reactdocgen), this option is deprecated and will be removed in Storybook 12.
